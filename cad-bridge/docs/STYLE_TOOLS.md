# Вес линии и SOLID-штриховка

Исторический выпуск `2026-10-06-style-tools` расширил общий AutoCAD 2027 MCP
на три вызова. Для него были собраны сервер и плагин, пройдены 708 offline-тестов;
настоящий stdio MCP-клиент подтвердил 42 инструмента и корректные новые схемы.
2026-10-06 пользователь подтвердил живой PASS: вес слоя, веса объекта в трёх
режимах, белая SOLID-заливка окружности и ACI30-заливка прямоугольника,
отказы без изменений. Пять тестовых объектов и уникальный слой удалены.

Эти исходники уже включены в `Projects/cad-bridge/upstream/dwg-mcp` вместе
с локальными исправлениями. Подготовленный импорт ещё не слит и не развёрнут.
Текущий исходный мост `D:\CAD-Automation\upstream\dwg-mcp` остаётся активным
до согласованного переключения после merge. Исторический live PASS не является
подтверждением загрузки DLL из нового checkout или проверки AutoCAD 2026.

## Инструменты

| Вызов | Основные параметры | Результат |
| --- | --- | --- |
| `dwg_set_lineweight` | `handles`: массив строк; `lineweight_mm`: число; `mode`: `explicit` / `by_layer` / `by_block` | Изменённые handles, count, вес и режим |
| `dwg_set_layer_lineweight` | `layers`: массив имён существующих слоёв; `lineweight_mm`: число | Изменённые слои, count, вес |
| `dwg_create_hatch` | `boundary_handle`: одна окружность или замкнутая плоская lightweight Polyline; опциональные layer, color_index либо color_rgb, associative, draw_order | Handle новой Hatch и её параметры |

Примеры параметров обычных MCP-вызовов:

```json
{"handles":["24C"],"lineweight_mm":0.30}
{"handles":["24C"],"mode":"by_layer"}
{"layers":["НВ","НК1","НК2"],"lineweight_mm":0.30}
{"boundary_handle":"24D","color_rgb":[255,255,255]}
```

Handles в примерах условные. Агент получает актуальные handles из создания
или чтения объектов нужного активного чертежа.

Вес всегда задаётся в миллиметрах, независимо от единиц координат чертежа.
Допустимы точные значения AutoCAD: 0, 0.05, 0.09, 0.13, 0.15, 0.18, 0.20, 0.25,
0.30, 0.35, 0.40, 0.50, 0.53, 0.60, 0.70, 0.80, 0.90, 1.00, 1.06, 1.20, 1.40,
1.58, 2.00, 2.11. Для by_layer/by_block поле lineweight_mm надо опустить.
LWDISPLAY не меняется: отображение толщины включается пользователем отдельно.

Заливка использует только паттерн SOLID, без островов. Граница должна находиться
в текущем пространстве. По умолчанию используется её слой, цвет ByLayer,
associative=true, draw_order=above_entities. Белая заливка задаётся настоящим RGB
[255,255,255]. above_entities поднимает заливку над другими объектами и контур
над заливкой; below_entities опускает заливку вниз. Слои должны существовать.

Все цели проверяются до записи. Заблокированные, зависимые от Xref, отсутствующие
или недоступные цели отклоняют весь запрос. Вес меняется одной транзакцией;
создание Hatch также выполняется одной транзакцией. Общий Undo для нескольких
MCP-вызовов не добавлялся. Чертёж автоматически не сохраняется.

## Как выпущено изменение

1. Общий сценарий разобран на независимые операции с параметрами.
2. Методы MCP находятся в `upstream/dwg-mcp/src/server/Tools/EntityStyleTools.cs`,
   обработчики — в `upstream/dwg-mcp/src/shared/Handlers/`, проверки ввода —
   в `upstream/dwg-mcp/src/shared/Cad/` относительно `cad-bridge/`.
3. Команды зарегистрированы в dispatcher, схемы и toolset modify обновлены.
4. Проверены реальные SDK-схемы, значения, ошибки и режим read-only.
5. Патч `patches/dwg-mcp-lineweight-hatch.patch` сохраняет применённые изменения;
   исходники импорта уже содержат их. Повторно применять патч не требуется.
   Последующие изменения отслеживает Git monorepo `Projects`.
6. Пользователь загрузил обновление и запустил живую проверку. PASS и cleanup
   подтверждены; готовность нативных операций отмечена в WORK_STATUS.md.

Подход опирается на [Autodesk LineWeight enum](https://help.autodesk.com/cloudhelp/2026/ENU/OARX-ManagedRefGuide/files/OARX-ManagedRefGuide-Autodesk_AutoCAD_DatabaseServices_LineWeight.html)
и [пример создания Hatch](https://help.autodesk.com/cloudhelp/2022/ENU/OARX-DevGuide-Managed/files/GUID-89CAED67-B3A0-4045-9D8B-9034D67E8D91.htm).
Плагин 2027 собирается под net10.0-windows со ссылками на установленные DLL
AutoCAD 2027; `plugin-acad26` использует net8.0-windows и compile-only ссылки
Autodesk AutoCAD.NET 25.1.0. Подробности — в `docs/TEAM_SETUP.md`.

## Offline-проверка из monorepo

После клонирования `Projects` пользователь переходит в каталог моста:

```powershell
cd .\Projects
cd .\cad-bridge
python .\tools\check-style-mcp.py --target 2027
# Проверка того же профиля для маршрутизации на AutoCAD 2026:
python .\tools\check-style-mcp.py --target 2026
```

Без `--live` проверяются только список и схемы; AutoCAD не вызывается.
Скрипт по умолчанию запускает собственную собранную DLL
`upstream/dwg-mcp/src/server/bin/Release/net8.0/Bimwright.Dwg.Server.dll`, target
2027 и `dotnet` из PATH. Поддерживаются явные `--server`, `--target 2026` /
`--target 2027` и `--dotnet`, например:

```powershell
python .\tools\check-style-mcp.py --server 'C:\CAD\build\Bimwright.Dwg.Server.dll' --target 2026 --dotnet 'C:\Program Files\dotnet\dotnet.exe'
```

Python запускается из среды с `anyio` и `mcp`. Сборка и требования к SDK описаны
в `docs/TEAM_SETUP.md`. Offline-проверка не меняет зарегистрированный MCP.

## Согласованная загрузка и живая проверка после merge

Для первого перехода на импортированный checkout DLL загружается после merge
и согласованного переключения моста. При дальнейшей разработке пользователь
может отдельно включить live-проверку тестовой сборки до merge.
Пользователь закрывает AutoCAD, устанавливает согласованный ZIP для своего года
по `packaging/team/INSTALL-RU.md` и запускает новую сессию. DLL предыдущей сессии
сама не обновляется. Сохранение существующих чертежей пользователь решает
самостоятельно. Регистрация MCP и глобальные инструкции исходного компьютера
не переключаются автоматически при импорте или сборке.

В пустом тестовом чертеже Model запустить проверку; имя после --document должно
совпадать с document_name текущего чертежа. Во время теста не переключать вкладки.

```powershell
python .\tools\check-style-mcp.py --target 2027 --live --document 'Чертеж1.dwg'
# Для AutoCAD 2026: тот же вызов с --target 2026 и соответствующим плагином.
```

Живой режим требует отдельного разрешения пользователя. Он
создаёт собственный уникальный слой и объекты, проверяет веса и две штриховки,
затем удаляет их. Для удаления пустого тестового слоя использует доверенный C#
через dwg_send_code временного клиента. При неопределённом результате мутации
повторы блокируются; выводятся имена и handles для разбора оставшихся объектов.
